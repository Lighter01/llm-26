# Дополнительные измерения

Здесь сохранены семь неизменённых JSON из технических проверок реализации 5–6 ноября 2026 года. Это дополнение к штатным экспериментальным runs, а не результаты нового запуска. Файлы перенесены с проверкой побайтового совпадения SHA-256.

| Файл | Назначение и поля |
| --- | --- |
| [c3-demo.json](c3-demo.json) | Отдельный baseline-demo с шестью QA-вызовами, включая большой синтетический вопрос и UI; содержит ответы, времена и ресурсные измерения. Это **не финальный QA20**. |
| [c4-evidence.json](c4-evidence.json) | Дополнительная проверка десяти коллекций и сохранённых метрик: `runs` содержит ID, схемы, число записей, `metrics_recomputed_exactly`, `collection_allocated_bytes` и `collection_apparent_bytes`. |
| [c4-g1.json](c4-g1.json) | Производный анализ splitter: Markdown, Recursive и source_map H4. |
| [c4-g2.json](c4-g2.json) | Производный анализ размера и overlap относительно выбранной G1-базы. |
| [c4-g3.json](c4-g3.json) | Производное сравнение dense и hybrid BM25/RRF. |
| [c4-g4.json](c4-g4.json) | Два независимых сравнения HNSW и BM25 с одной hybrid-базой G3. |
| [c4-g5.json](c4-g5.json) | Производное сравнение способов передачи заголовков эмбеддеру на dense-базе. |

Штатные retrieval-runs сохраняют `run.json`, `metrics.json`, `per_question.jsonl`, полный `chunks_manifest.jsonl`, `relevance.json` и снимки config/gold. Их имена и зависимости заданы в [study.yaml](../../configs/experiments/study.yaml); общая таблица — [retrieval_comparison.csv](../retrieval_comparison.csv). Групповые JSON получены из этих файлов: сравниваются метрики одних и тех же 20 вопросов, дельты к базе и результаты по категориям. Это анализ прежних runs, без новых запросов к модели. Их можно проверить по manifest/gold/hits; готового публичного экспортёра именно этого группового формата нет. Независимый пересчёт метрик и чисел отчёта выполняет [сборщик отчёта](../../report/scripts/build_report_artifacts.py).

В C3 измерялись сумма PSS процессов своего runtime и NVML всей GPU с фоновым потреблением. Qdrant и сам измеритель не входят в дерево PSS; шаг около 0.5 с может пропускать короткие пики. CUDA/GGUF, обычные файловые кэши и профиль 8192/1536/256 соответствуют условиям той пробы. Большой вопрос с 6220 входными токенами — техническая нагрузка, не дополнительный gold-вопрос. Пики C3 нельзя приписывать финальному QA20 или считать гарантией для любой нагрузки.

В C4 `allocated` — занятые дисковые блоки коллекции (`du -s -B1`), `apparent` — логический размер (`du -sb`), включая sparse/preallocated WAL. Это не RAM/VRAM и не только float32-векторы. Размер измерен после readiness в тогдашнем Docker named volume; нынешний bind mount [data/qdrant](../../data/qdrant/) не меняет исторические условия. Эти ресурсные замеры не собираются автоматически каждым retrieval-run и могут отличаться при новом запуске.

Внутренние поля `checkpoint`, `next_task`, `pause_required`, прежние пути и сообщения о тестах описывают состояние на момент сохранения; это исторические метаданные, не текущие инструкции или зависимости. Одноразовые скрипты и журналы разработки не требуются для чтения данных и не входят в этот каталог. [Описание проб](../../docs/rag/TECHNICAL_PROBES.md), [анализ экспериментов](../../docs/rag/EXPERIMENTS.md), [готовый отчёт и воспроизведение](../../report/LAB2_REPORT.md#9-данные-и-воспроизведение-отчёта) объясняют методы и ограничения. Финальные ответы и заполненная agent-assisted рецензия находятся отдельно в [qa_final](../qa_final/qa_review.csv).
