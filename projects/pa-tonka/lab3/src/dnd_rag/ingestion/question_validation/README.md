# Валидатор оценочных вопросов

Самостоятельный модуль подготовки данных: проверяет один сырой YAML по трём готовым Markdown-книгам и `source_map.jsonl`. Работает локально без моделей, индекса, сети и запуска сборщика/экспортёра. Нужны Python ≥3.13, uv и PyYAML (runtime-зависимость проекта).

## Запуск

Из корня `lab2`, с явно выбранным набором и ревизией корпуса:

```bash
uv run python -m dnd_rag.ingestion.question_validation \
  --input data/questions/questions_codex.yaml \
  --corpus data/markdown/5etools/c3d53956346388b222aaaaf4637776f563e201b8 \
  --output-dir data/questions/validated
```

Можно выбрать любой другой сырой файл той же схемы, например `data/questions/raw/questions.yaml`. Наборы автоматически не объединяются. Коды выхода: `0` — PASS, `1` — ошибка проверки/ввода-вывода, `2` — неверные аргументы.

В Python:

```python
from dnd_rag.ingestion.question_validation import validate_questions

result = validate_questions(input_path, corpus_dir, output_dir)
print(result.report['status'])
print(result.questions_path)  # Path при успехе, None при ошибках проверки
```

`ValidationResult` содержит `report: dict` и `questions_path: Path | None`. Ошибки входов собираются в отчёт; невозможность записать сам отчёт или создать выходной каталог может вызвать `OSError`. CLI показывает такую ошибку без traceback.

## Входной контракт v1

- Корень содержит только `schema_version: 1` и `questions`.
- Ровно 23 уникальных ID: `phb_01..05`, `dmg_01..05`, `mm_01..05`, `multi_01..05`, `insufficient_01..03`; порядок произвольный и сохраняется.
- Вопрос: `id`, непустые строки `question` и `reference_answer`, boolean `answerable`, список `evidence`. Первые 20 ответимы и имеют evidence; последние три имеют `answerable: false` и `evidence: []`.
- Факт: непустая строка `fact`, непустой список `alternatives`.
- Альтернатива: `file` из `xphb.md`/`xdmg.md`/`xmm.md`, непустой список строк `heading_path` от H1 без названия книги и непустая дословная строка `quote`.

Лишние/пропущенные поля, неправильные типы, дубли ключей и несколько YAML-документов отклоняются. Координат в сыром YAML нет. Пустота строк проверяется без изменения текста. Для каждого однокнижного факта нужна альтернатива своей книги. У `multi_*` пересечение наборов книг альтернатив всех фактов должно быть пустым. В каждой однокнижной пятёрке нужен вопрос минимум с двумя разными путями своей книги среди альтернатив; найденные пути перечисляются в отчёте.

## Цитаты и координаты

Сопоставление строгое: учитываются все точные вхождения внутри всех диапазонов заданного пути карты. Повторные пути допустимы; одно абсолютное совпадение засчитывается один раз. Ноль вхождений и неоднозначность — ошибки с ID, номерами факта/альтернативы и кандидатами. Уточните путь или расширьте дословную цитату.

Координаты относятся к **body без front matter и одного пустого разделителя**:

- `start_char`, `end_char`: Unicode code points, полуинтервал `[start_char, end_char)`;
- `line_start`, `line_end`: строки с 1, обе границы включены;
- последняя строка определяется символом `end_char - 1`: завершающий LF цитаты не добавляет следующую строку.

Body читается без нормализации; переносы книг должны быть LF. Цитаты не обрезаются и не расширяются до целых строк. YAML `|-` и `|` дают разные строки, и проверяется именно разобранное значение. Unicode-разделители строк при сохранении экранируются, чтобы YAML-парсер не изменил их при повторном чтении.

## Результат и отчёт

При полном успехе `questions.yaml` сохраняет поля и значения вопросов и добавляет координаты каждой альтернативе. В корне появляются `raw_input_sha256` и паспорт `corpus`: `files[имя].body_sha256`, `source_map_sha256`. Raw и карта хэшируются по исходным байтам, body — по его UTF-8 представлению. Абсолютные пути и время запуска не добавляются. Одинаковые входы дают побайтно одинаковый YAML.

`validation_report.json` содержит статус, счётчики, ошибки, распределение альтернатив по книгам/разделам, пути однокнижных вопросов и кандидатов на межраздельные вопросы. `sources` и `sections` считают структурно корректные объявления альтернатив; `counts.matched_alternatives` — однозначно найденные цитаты. Пути записей имеют индексы с 0; `question_number`, `fact_number`, `alternative_number` и номера строк файлов — с 1.

Публикация каждого файла выполняется через временный файл и `os.replace`. Отчёт записывается перед YAML; ошибка записи отчёта не публикует новый набор. При ошибках проверки предыдущий YAML сохраняется без изменения; `output_state: previous_preserved` и CLI явно сообщают, что он относится к предыдущему успешному запуску. Другие состояния — `written` и `not_written`. При ошибке замены YAML отчёт обновляется до FAIL. Входы не изменяются.

**PASS подтверждает структуру и привязку цитат.** Английский язык, истинность ответов, достаточность фактов, необходимость книг/разделов, полнота альтернатив и случаи недостаточных данных требуют ручной смысловой проверки.

## Проверки

```bash
uv run --group test python -m pytest tests/ingestion/question_validation
uv run --group lint ruff check src/dnd_rag/ingestion/question_validation tests/ingestion/question_validation
uv run --group lint ruff format --check src/dnd_rag/ingestion/question_validation tests/ingestion/question_validation
```

Тесты создают маленькие книги и карту в pytest tmp; покрывают схему, точные координаты, неоднозначность, ошибки публикации, сохранность входов и предыдущего результата, CLI и воспроизводимость в отдельных процессах. Реальный smoke выполняется командой запуска выше, без пересборки корпуса.

Проверка 2026-11-05: **78 тестовых сценариев прошли**, Ruff lint/format-check успешны. Реальный `questions_codex.yaml` на указанной ревизии получил PASS: 23 вопроса (20+3), 59 фактов, 78 однозначных цитат; распределение альтернатив — XPHB 28, XDMG 28, XMM 22. Все срезы, строки и хэши независимо сверены; два процесса с разными hash seeds дали одинаковые YAML и JSON-отчёт, входы остались неизменными. Отдельно подтверждены два совпадения реального пути `Monsters A to Z / Gray Oozes / Gray Ooze` и сохранение предыдущего YAML при FAIL.
