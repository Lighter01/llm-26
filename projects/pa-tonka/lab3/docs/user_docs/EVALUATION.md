## Набор и условия сравнения

[data/tasks/lab3.yaml](../../data/tasks/lab3.yaml) содержит 15 фиксированных заданий на английском:

| Тип | Задач | Реплик на задачу |
| --- | ---: | ---: |
| Одиночная | 8 | 1 |
| Короткий диалог | 4 | 3 |
| Длинный диалог | 3 | 9 |

Всего 47 реплик на клетку, 60 выполнений задач / 188 реплик в матрице own/Codex × off/budgeted. `item` — одна задача, `turn` — реплика, `session` — её диалог. Следующая задача и следующая конфигурация получают новую сессию. Агенту передаётся только текущий пользовательский input; gold, checks и rubric исключены из модельного запроса.

Для 10 retrieval-реплик заранее проверены quote, body/hash, раздел, Unicode-координаты и строки исходника. Некоторые правила повторяются: это не 10 независимых тем. Quote-only resolver допускает ровно одно совпадение в секции; фактически найденные фрагменты ([hits](GLOSSARY.md#hit)) не используются как эталон.

Общий fingerprint связывает dataset/selection, corpus/index/build, каталог, GGUF/template и рабочие prompts/tools/config/adapter. Все четыре клетки должны иметь одинаковый common fingerprint; профиль и Git HEAD сохраняются отдельно.

## Порядок оценивания

1. `evaluate-agents` сохраняет ответы и формальные scores; смысловые критерии остаются `pending`.
2. Заполните `review.csv` по реальным ответам, tool results и traces.
3. `score-agents` воспроизводит оценки офлайн; `--upload-scores` отправляет их в Langfuse.
4. `summarize-agents` строит comparison для совместимых сохранённых прогонов.

Исправления evaluator применяются одинаково ко всем клеткам. Новая генерация требует нового run-id; переоценка не заменяет исходный ответ.

## Файлы одного запуска

Каталог — `results/lab3/<run-id>/`:

| Файл или каталог | Содержание |
| --- | --- |
| `run.json`, `manifest.json` | Статусы, provenance, входной dataset и полный перечень chunks индекса. |
| `turns.jsonl`, `tool_calls.jsonl` | Исходные ответы, usage, события, квитанции tools и первоначальные scores. |
| `review.csv` | Отдельные смысловые критерии с явным методом и обоснованием. |
| `scored_turns.jsonl`, `scored_tool_calls.jsonl`, `metrics.json` | Единое производное представление после recompute. |
| `raw/own`, `raw/codex` | Полный журнал собственного агента; для Codex — stdout/stderr/argv, копия JSONL-журнала сессии, логи экспорта и ответ API Langfuse. |
| `citations/<session>.json` | Реестр фактических источников, включая номера до summary. |

[Wire-журнал](GLOSSARY.md#wire) хранит фактические Responses-запросы до и после преобразования proxy, ответы и native count/usage, включая compaction. [Экспортер Codex](../../configs/baseline/README.md#экспортер-что-он-переносит) восстанавливает вход генерации по JSONL-журналу событий (rollout); после compaction он может отличаться от реально отправленного HTTP-запроса. Неизвестные значения остаются `null`; локальная API-стоимость равна 0.

## Метрики и знаменатели

| Метрика | Что считается |
| --- | --- |
| Task success | Все обязательные критерии всех проверяемых turns задачи. Известная ошибка делает задачу failed. |
| Completion | Все запланированные turns, completed runtime, настоящий trace и известные input/output usage. |
| History correctness | Явная оценка размеченных history turns; отдельно до/после фактического compaction. |
| Tool correctness | Среднее формальных критериев выбора, аргументов и результатов на применимых turns. |
| Retrieval | P/R@1/5/10, MRR@10 и evidence coverage по полному manifest. |
| Citation validity | Доля разрешённых номеров среди уникальных использованных `[n]` на turn. Без номеров — N/A. |
| Ресурсы | Токены, API-cost, latency, model/tool calls и максимальный native input, включая summary при доступных данных. |

Failed/skipped/incomplete остаются в знаменателе. Success rate равен `null`, пока неизвестен хотя бы один исход; pending показывает незаполненные критерии и у уже известных failed tasks. Завершённое выполнение не равнозначно правильному ответу.

Retrieval relevance требует одинаковых file/hash и пересечения ≥ 50% меньшего span. Короткая выдача не уменьшает знаменатель Precision, повторные chunks не улучшают покрытие. Несколько поисков сначала усредняются внутри размеченного turn, затем между turns. Для обязательного пропущенного поиска — 0 и `missing_expected_call`, для неразмеченного — N/A. Requested/returned limits сохраняются.

Tool errors считаются по всем завершённым попыткам, включая исправленные validation errors и ожидаемые conflicts. Неизвестный результат начатого вызова не превращается в успех или дополнительную ошибку. Группы history до/после compaction различаются; их сравнение не доказывает причинного эффекта summary.

## Смысловые критерии

Поля `review.csv`: `case_id`, `turn`, `criterion`, `description`, `value`, `method`, `evidence`, `category`.

| Поле | Как заполнить |
| --- | --- |
| `value` | 0 или 1; пустое значение остаётся pending. |
| `method` | `human` или `agent-assisted`, согласно фактическому способу оценки. |
| `evidence` | Конкретный ответ, tool result или trace, объясняющий решение. |
| `category` | Категория ошибки при необходимости. |

Повторный/неизвестный turn или criterion отклоняется. Agent-assisted оценка не называется человеческой. Правильный вызов не компенсирует пропущенное объяснение; дополнительные утверждения, противоречащие проверяемому правилу, также учитываются.

Механические проверки сверяют состав, суммы, party arguments, фильтры, required counts, conflict/search_exhausted и реальные loot records. Для исправленного вызова оценивается финальная калькуляция; журнал предыдущих попыток остаётся. Необходимое совпадение имени/числа не заменяет смысловую проверку количества, редкости, источника и полноты ответа. Нормализация запятых и Potion(s)/Scroll(s) не приравнивает разные предметы.

Номера `[1]` и `[1, 2]` проверяются по реестру текущего диалога. Это проверка существования ссылки; поддержку утверждения источником оценивает rubric.

## Повторная оценка и исходные данные

- Проверенные stat blocks допускают повторное использование: предыдущий lookup или успешный build/evaluate с точными name/ID/CR/XP. Ошибочный/conflict result не служит источником.
- Для hoard прежний CR владельца используется при явно названной той же сущности; совпадающий CR другого монстра недостаточен.
- Первый случайный output сохраняется. Повторный roll не отменяет его; подмена ledger отличается от потери памяти после summary.
- Если старый Codex capture потерял stdout, восстанавливаются только новые завершённые `function_call_output` из wire. Исходные call IDs, незавершённые запросы и повторная сериализация исключаются; реальные повторные вызовы учитываются отдельно.

`raw_records.tools` и `tool_calls.jsonl` сохраняют исходные receipts. Поле tools в первоначальном turn уже могло пройти initial scoring/recovery; единая итоговая версия — scored-файлы. Восстановленные записи имеют provenance. Эти представления проверяются отдельно, без переписывания оригиналов ради совпадения счётчиков.

`evaluation_provenance` фиксирует SHA256 review CSV и evaluator/evidence/metrics contracts. Полные raw directories сохранены локально и исключены из Git; перенос и воспроизведение описаны в [results](../../results/lab3/README.md).

## Как читать Langfuse

SDK 5 / Compose 4 используют event-based Experiments. Служебная запись Langfuse ([observation](GLOSSARY.md#observation)) связывает задание датасета с настоящим trace через атрибуты OpenTelemetry. Последующее чтение API Langfuse ([readback](GLOSSARY.md#readback)) проверяет связи, записи генераций/usage и полный последний ответ ассистента на соответствующий пользовательский запрос.

**Experiment Scores** completion/task success относятся к задачам прогона; **Trace Scores** — к отдельным репликам. Автоматические Latency/Error Count/Total Cost служебных observations не заменяют время и исходы агента. Для анализа используйте реальные agent traces, AgentReply/run wall и generation usage. Снимки и примеры — в [отчёте](../../report/LAB3_REPORT.md#скриншоты-реального-langfuse), маршрут показа — в [DEMO](DEMO.md).
